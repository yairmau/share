# AGENTS.md

This repo is the source for **yairmau.com/share**: Yair Mau's landing page and
write-ups for friends and family — things he's written or put together that
don't belong in his other, more technical books.

It's a **Quarto website** (`project: type: website` in `_quarto.yml`), built
and deployed the same way as his other Quarto sites: `quarto render` builds
into `docs/`, and GitHub Pages serves `docs/` from `main`, so **pushing to
`main` publishes the site**.

## Before pushing

- **Everything here is public.** Anyone with the link can read the site and
  this repo's source. Do not add private family details, contact info, or
  anything Yair hasn't clearly asked to publish.
- **Show Yair the finished page and get his OK before pushing.** A push is a
  publish.
- Write commit messages in plain English, e.g. `Add page: <title>`.

## Adding a page

1. Pick a short, lowercase, hyphenated slug and make a folder with that name
   containing `index.qmd` (see `research-vault/`, `five-levels-ai-agents/`,
   `i-chatbot/` for examples). The page will live at
   `yairmau.com/share/<slug>/`.
2. Start the file with YAML front matter:

   ```yaml
   ---
   title: Page title
   author: Yair Mau
   date: YYYY-MM-DD
   description: One sentence shown under the title and on the landing page.
   ---
   ```

3. Write the body in Markdown (Quarto's Pandoc-flavored Markdown: tables,
   fenced code blocks, raw HTML where needed — e.g. a captioned `<img>`).
   Don't repeat the title as an `# H1`; the title block already prints it.
4. Add the new page to the `listing: contents:` list in `index.qmd` so it
   shows up on the landing page, newest first (the listing sorts by `date`,
   so order in the YAML list doesn't matter).
5. Render and check the page locally (`quarto render <slug>/index.qmd`)
   before asking Yair to review it.

## Files

| Path | Purpose |
| --- | --- |
| `_quarto.yml` | Site config: navbar, favicon, Google Analytics ID, theme (`flatly` + `custom.scss`), fonts, the `includes.html` header include |
| `custom.scss` | Sass overrides on top of the `flatly` Bootstrap theme — title-block spacing, link styling, etc. |
| `styles.css` | Plain CSS additions that don't need Sass variables |
| `includes.html` | Extra `<head>` tags: `noindex` meta, favicon fallbacks for older browsers/phone home screens |
| `index.qmd` | Landing page. Uses a Quarto `listing` to list every page named in its `contents:`, newest first |
| `<slug>/index.qmd` | One shared page each, plus any images it uses |
| `archive/logo/` | Favicon and nav logo source files |
| `archive/site_images/` | Other image assets not tied to a specific page |
| `docs/` | Build output — generated by `quarto render`, not hand-edited |

## Conventions

- **External links open in a new tab** via `link-external-newwindow: true` in
  `_quarto.yml` — don't add `target` attributes by hand, that's handled
  globally already.
- When citing AI chatbots as generic examples (not describing a specific
  product behavior), list **Claude, ChatGPT, and Gemini** together rather
  than just the first two — keep the list vendor-neutral.
- Don't edit `custom.scss`/`styles.css` or the navbar/theme in `_quarto.yml`
  unless asked. New pages should look like the existing ones.
- `noindex: true` behavior comes from the `<meta name="robots">` tag in
  `includes.html` — these pages are intentionally not meant to be indexed by
  search engines, only reachable by direct link.
- Quarto tables don't collapse into stacked "card" rows on narrow screens the
  way some Jekyll themes do — they just get a horizontal scrollbar. That's a
  deliberate choice not to introduce `data-label` markup for one-off tables;
  don't add responsive-table CSS unless asked.
